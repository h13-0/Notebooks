## 2.3 平台设备

### 2.3.1 平台设备的数据结构

```C
struct platform_device {
	const char	*name;
	int		id;
	bool		id_auto;
	struct device	dev;
	u64		platform_dma_mask;
	struct device_dma_parameters dma_parms;
	u32		num_resources;
	struct resource	*resource;

	const struct platform_device_id	*id_entry;
	/*
	 * Driver name to force a match.  Do not set directly, because core
	 * frees it.  Use driver_set_override() to set or clear it.
	 */
	const char *driver_override;

	/* MFD cell pointer */
	struct mfd_cell *mfd_cell;

	/* arch specific additions */
	struct pdev_archdata	archdata;
};
```

其成员：
- `const char *name` ：
	- 功能含义：设备名称标识符(可重复)
	- 维护方：
		- 通过设备树或ACPI进行配置，则在其初始化时设置
		- 对于动态加载的虚拟设备，驱动需要在内核模块中<font color="#c00000">设备注册前设置</font>
- `int id` ：
	- 功能含义：设备实例ID，用于区分同名设备
	- 维护方：驱动可指定ID类型，内核(总线)在注册时自动分配。驱动可设置的数值有：
		- `PLATFORM_DEVID_AUTO` ：请求内核自动分配
		- `PLATFORM_DEVID_NONE` ：将该设备注册为单例设备
- `bool id_auto` ：
	- 功能含义：标记ID是否为自动分配
	- 维护方：内核自动维护，驱动只读访问
- `struct device dev` ：
	- 功能含义：内嵌的标准设备
	- 维护方：<font color="#c00000">驱动必须配置成员</font>：
		- `.parent` 
		- `.release` ：当设备计数器归0时会被调用
- `u64 platform_dma_mask` :
	- 功能含义：设备特定的DMA掩码，优先级比 `dev.dma_mask` 高：
		- 若 `platform_dma_mask` 非零，则使用 `platform_dma_mask`
		- 否则使用 `dev.dma_mask` 
	- 维护方：驱动初始化前按需设置
- `struct device_dma_parameters dma_parms` ：
	- 功能含义：DMA传输参数
- `u32 num_resources` ：
	- 功能含义：设备资源指针的数组大小(即下一成员指向的资源数量)
	- 维护方：驱动必须配置
- `struct resource *resource` ：
	- 功能含义：描述设备所占用的硬件资源，如I/O内存地址范围、中断号、DMA通道等
	- 维护方：驱动静态定义或设备树解析
- `const struct platform_device_id *id_entry` ：
	- 功能含义：指向平台设备表的指针
	- 维护方：内核负责维护
- `const char *driver_override` ：
	- 功能含义：强制绑定的指定驱动
	- 维护方：用户通过 `sysfs` 等方式强制设置，随后内核维护，驱动禁止直接修改
- `struct mfd_cell *mfd_cell` ：
	- 功能含义：指向的MFD单元
	- 维护方：MFD驱动初始化，由MFD子系统管理
- `struct pdev_archdata archdata` ：
	- 功能含义：体系结构的特定数据
	- 维护方：由体系结构代码或特定平台代码设置，驱动通常不需要关心

## 2.4 平台驱动

### 2.4.1 平台驱动的数据结构

```C
struct platform_driver {
	int (*probe)(struct platform_device *);

	/*
	 * Traditionally the remove callback returned an int which however is
	 * ignored by the driver core. This led to wrong expectations by driver
	 * authors who thought returning an error code was a valid error
	 * handling strategy. To convert to a callback returning void, new
	 * drivers should implement .remove_new() until the conversion it done
	 * that eventually makes .remove() return void.
	 */
	int (*remove)(struct platform_device *);
	void (*remove_new)(struct platform_device *);

	void (*shutdown)(struct platform_device *);
	int (*suspend)(struct platform_device *, pm_message_t state);
	int (*resume)(struct platform_device *);
	struct device_driver driver;
	const struct platform_device_id *id_table;
	bool prevent_deferred_probe;
	/*
	 * For most device drivers, no need to care about this flag as long as
	 * all DMAs are handled through the kernel DMA API. For some special
	 * ones, for example VFIO drivers, they know how to manage the DMA
	 * themselves and set this flag so that the IOMMU layer will allow them
	 * to setup and manage their own I/O address space.
	 */
	bool driver_managed_dma;
};
```

其成员：
- `int (*probe)(struct platform_device *)` ：
	- 功能含义：设备初始化入口函数
	- 维护方：<font color="#c00000">驱动必须实现</font>
- `int (*remove)(struct platform_device *)` ：
	- 功能含义：旧的设备移除回调。已弃用，应当使用无返回值的 `remove_new` 
	- 维护方：不建议使用
- `void (*remove_new)(struct platform_device *)` ：
	- 功能含义：现代设备移除回调
	- 维护方：<font color="#c00000">驱动必须实现</font>
- `void (*shutdown)(struct platform_device *)` ：
	- 功能含义：系统关机时的设备处理回调
		- 注：需要关注[[Linux设备模型#^ce9oct|电源管理优先级]]事项
	- 维护方：驱动可选实现
- `int (*suspend)(struct platform_device *, pm_message_t state)` ：
	- 功能含义：设备挂起回调，根据目标状态进入不同的低功耗模式
		- 其参数 `state` 
	- 维护方：驱动按需配置
- `int (*resume)(struct platform_device *)` ：
	- 功能含义：设备恢复回调，退出低功耗模式
	- 维护方：驱动按需配置
- `struct device_driver driver` ：
	- 功能含义：平台驱动内嵌的标准驱动结构
	- 维护方：<font color="#c00000">驱动必须配置成员</font>：
		- `name` 
		- `owner` 
- `const struct platform_device_id *id_table` :
	- 功能含义：设备-ID匹配表
	- 维护方：
- `bool prevent_deferred_probe` ：
	- 功能含义：禁用延迟探测机制
	- 维护方：
- `bool driver_managed_dma`
	- 功能含义：


### 2.4.2 平台驱动相关API
#### 2.4.2.1 注册平台驱动

注册单个平台驱动：

```C
#define platform_driver_register(drv) \  
        __platform_driver_register(drv, THIS_MODULE)

/**
 * __platform_driver_register - register a driver for platform-level devices
 * @drv: platform driver structure
 * @owner: owning module/driver
 */
int __platform_driver_register(struct platform_driver *,  
                                    struct module *);
```

注册一系列平台驱动：

```C
int __platform_register_drivers(struct platform_driver * const *drivers,
                              unsigned int count, struct module *owner);
void platform_unregister_drivers(struct platform_driver * const *drivers,
                                 unsigned int count);
```

若上述驱动中有一个注册失败，则已通过该API注册的驱动会按照相反的顺序注销。
