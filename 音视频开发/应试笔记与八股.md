# 3 H.264编码是怎样的

考查企业：
- 影石 嵌入式

1. H.264编码是一种数字视频编解码标准，其主要依靠于帧内预测、帧间预测、整数变换与量化以及熵编码实现
2. 其核心概念为I、P、B帧，分别为：
	- I帧：不依赖于其他帧的视频帧，只使用帧内压缩，<font color="#c00000">是随机访问的切入点</font>
	- P帧：前向预测帧，依赖于P帧之前的帧进行帧间压缩
	- B帧：双向预测帧，依赖于B帧前后的帧进行帧间压缩
3. 此外，还有一些功能性的概念，比如IDR帧，可以阻断该帧前后的帧间依赖

# 4 在使用FFmpeg封装MP4文件时，如果系统发生异常断电，如何保证之前的视频文件不损坏

1. 文件损坏的根本来源是由于MP4文件的解析依赖于其元数据，该元数据包含了视频的时长、引索、编解码参数等
2. 而FFmpeg通常在录制结束后才会把元数据写入到MP4文件的头部和尾部，一旦提前断电，则会由于缺少元数据而无法解码
3. 在使用FFmpeg时，可以将其录制为碎片化MP4或ts格式，从而避免避免意外断电造成的损坏(如果录制为ts格式，则需要后期重新封装为MP4文件)

# 5 MP4的数据格式和基本封装格式是什么样的 ^ybzsdo

考察企业：
- 百度 小度 嵌入式

1. MP4数据格式主要是由一系列的box组成的，其主要有：box大小、数据类型、box负载组成。
2. 其数据类型主要由 `moov` 和 `mdat` 组成：
	1. `moov` 主要记录<span style="background:#fff88f"><font color="#c00000">整个</font></span><font color="#c00000">MP4的元数据</font>和<font color="#c00000">各轨道的Chunk索引信息</font>
	2. `mdat` <font color="#c00000">会交错存储不同轨道的音视频数据</font>，每个数据按Chunk分包传递
3. 通常一个MP4中只有一个 `moov` ，其位置不固定：
	1. 对于视频录制场景，只有结束录制时，才知道其部分元数据，<font color="#c00000">因此通常存放到文件尾</font>
	2. 当从网络下载、或者重新转码时，通常放到文件头

# 8 如何优化Wi-Fi图传的卡顿问题

考察企业：
- 百度 小度 嵌入式
- 拓竹 嵌入式 一面

1. 首先要确定图传卡顿的原因，其常见原因有：
	1. 编码产生的码流超过无线通信容量
	2. Wi-Fi干扰导致的丢包、重传和速率下降
	3. 网络队列积压，队列中旧视频帧太多
	4. 可靠传输的重传阻塞后续数据
	5. 接收端抖动缓冲过大或过小
	6. 关键参考帧丢失，导致后续多帧无法解码
	7. 编码、传输、解码速度短时间不匹配
2. 无线链路层面：
	1. **选择合适的信道与频段**
	2. **调整信道带宽**：例如在干扰严重时，从80MHz降低到40或20MHz
	3. **动态调整Wi-Fi速率**：在干扰严重时，降低速率可以降低重传率等
	4. 调整MAC重传次数
	5. 调整Wi-Fi的发射功率等
3. 网络层面：
	1. **视频帧分包**：编码后的一帧往往大于网络MTU，因此需要对帧分包发送，并设计帧序号、包序号、时间戳、帧类型等必备字段
	2. **选择性重传**：对于来不及重传的、或者P/B等不重要的帧，可以放弃重传
	3. **避免缓冲区膨胀**(Bufferbloat)：例如发送或接收队列中卡了2s的视频帧，导致的延迟
	4. QoS和优先级调度：
	5. 动态前向纠错：
		- 在带宽富裕时，为无线链路增加校验包，这样少量丢包时可以避免重传耗时
		- 带宽不富裕时关闭此功能
4. 视频流层面：
	1. **拥塞控制和带宽估计**：可以周期性采集接收端实际吞吐量、丢包率、RTT、时延、发送端队列长度等，<font color="#c00000">估计实际可用带宽</font>；<font color="#c00000">随后在必要时主动降低码率</font>、降低帧率等。
	2. **平滑发包**：例如当编码完I帧时，可能会产生很大的发送数据量；具体实现为将一帧的数据包在一段时间内平滑发送，而不是一次性全部塞入socket。
	3. **使用RTP/RTCP代替TCP/UDP**：
	4. 分离控制信令与视频数据：可以使用不同的端口、不同队列、或者不同逻辑流，并配合不同的优先级策略
	5. I帧重传(PLI/FIR)：当I帧丢失时，可以使用PLI请求重传图像、用FIR刷新解码器或请求新的关键帧

# 9 YUV420和YUV422之间有什么区别

# 10 GOP是什么

1. GOP字面意思是<font color="#9bbb59">Group of Pictures</font>，是一组连续编码帧组成的单元。
2. 可以简单理解为从一个I帧开始、到下一个I帧之前结束的区间内，帧构成的集合。
3. 通常来说，GOP越长压缩率越高，但是随机访问(seek)和恢复时间更差

# 11 SPS和PPS是什么，通常存储在哪个地方

考察企业：
- 大疆 嵌入式 一面

1. SPS和PPS是H.264/AVC系列中的核心概念，具体为：
	1. SPS(<font color="#9bbb59">Sequence Parameter Set</font>)是保存一整段视频序列的全局参数，例如：
		- 分辨率
		- 帧结构
		- 编码参数等
	2. PPS(<font color="#9bbb59">Picture Parameter Set</font>)是保存更偏向单帧/图像级别的编码参数，例如：
		- 熵编码方式
		- QP相关参数
		- slice相关配置
2. 在裸H264流中，通常夹在视频流的IDR帧之前进行发送
3. 当封装为MP4文件时，其通常存储于moov的配置结构中
4. 在RTSP、RTP中，可以在H264码流中发送，也可以通过SDP带外发送

# 12 VPS是什么

1. <font color="#9bbb59">VPS</font>是<font color="#9bbb59">Video Parameter Set</font>，是H265中新增的视频参数集，比SPS的层级更高，主要包含整个视频层级的参数

# 13 讲一下Annex-B是什么，和AVCC的区别是什么

1. Annex-B是H264中NAL的单元封装方式，其：
	1. 常见起始码为：
		1. `00 00 01`
		2. `00 00 00 01`
	2. 包格式为 `[start code][NAL][start code][NAL]` 
2. AVCC是H.264在MP4等容器中使用的以长度为前缀的封装格式，其形式为：
	- `[length][NAL][length][NAL]`

# 14 DTS、PTS是什么

DTS、PTS通常由封装层携带和传输(例如MP4和TS)，其分别用于：
1. DTS是Decoding Timestamp，解码时间戳，用于指示该帧应该什么时候送入解码器
2. PTS是Presentation Timestamp，显示时间戳，用于指示该帧在什么时候显示

# 15 H264和H265的区别是什么

H265对H264的改进主要在于：
1. 压缩效率更高
2. 同质量下码率更低
3. 编码复杂度更高
4. 解码计算量通常更高
5. 延迟和兼容性问题可能更多
