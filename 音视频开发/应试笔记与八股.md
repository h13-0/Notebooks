# 3 H.264编码是怎样的

考查企业：
- 影石 嵌入式

1. H.264编码是一种数字视频编解码标准，其主要依靠于帧内预测、帧间预测、整数变换与量化以及熵编码实现
2. 其核心概念为I、P、B帧，分别为：
	- I帧：不依赖于其他帧的视频帧，只使用帧内压缩，<font color="#c00000">是随机访问的切入点</font>
	- P帧：前向预测帧，依赖于P帧之前的帧进行帧间压缩
	- B帧：双向预测帧，依赖于B帧前后的帧进行帧间压缩
3. 此外，还有一些功能性的概念，比如IDR帧，可以阻断该帧前后的帧间依赖

# 4 在使用FFmpeg封装MP4文件时，如果系统发生异常断电，如何保证之前的视频文件不损坏

1. 文件损坏的根本来源是由于MP4文件的解析依赖于其元数据，该元数据包含了视频的时长、引索、编解码参数等
2. 而FFmpeg通常在录制结束后才会把元数据写入到MP4文件的头部和尾部，一旦提前断电，则会由于缺少元数据而无法解码
3. 在使用FFmpeg时，可以将其录制为碎片化MP4或ts格式，从而避免避免意外断电造成的损坏(如果录制为ts格式，则需要后期重新封装为MP4文件)

# 7 如何优化Wi-Fi图传的卡顿问题

考察企业：
- 百度 小度 嵌入式

1. 首先要确定图传卡顿的原因，其常见原因有：
	1. 编码产生的码流超过无线通信容量
	2. Wi-Fi干扰导致的丢包、重传和速率下降
	3. 网络队列积压，队列中旧视频帧太多
	4. 可靠传输的重传阻塞后续数据
	5. 接收端抖动缓冲过大或过小
	6. 关键参考帧丢失，导致后续多帧无法解码
	7. 编码、传输、解码速度短时间不匹配
2. 无线链路层面：
	1. **选择合适的信道与频段**
	2. **调整信道带宽**：例如在干扰严重时，从80MHz降低到40或20MHz
	3. **动态调整Wi-Fi速率**：在干扰严重时，降低速率可以降低重传率等
	4. 调整MAC重传次数
	5. 调整Wi-Fi的发射功率等
3. 网络层面：
	1. **视频帧分包**：编码后的一帧往往大于网络MTU，因此需要对帧分包发送，并设计帧序号、包序号、时间戳、帧类型等必备字段
	2. **选择性重传**：对于来不及重传的、或者P/B等不重要的帧，可以放弃重传
	3. **避免缓冲区膨胀**(Bufferbloat)：例如发送或接收队列中卡了2s的视频帧，导致的延迟
	4. QoS和优先级调度：
	5. 动态前向纠错：
		- 在带宽富裕时，为无线链路增加校验包，这样少量丢包时可以避免重传耗时
		- 带宽不富裕时关闭此功能
4. 视频流层面：
	1. **拥塞控制和带宽估计**：可以周期性采集接收端实际吞吐量、丢包率、RTT、时延、发送端队列长度等，<font color="#c00000">估计实际可用带宽</font>；<font color="#c00000">随后在必要时主动降低码率</font>、降低帧率等。
	2. **平滑发包**：例如当编码完I帧时，可能会产生很大的发送数据量；具体实现为将一帧的数据包在一段时间内平滑发送，而不是一次性全部塞入socket。
	3. **使用RTP/RTCP代替TCP/UDP**：
	4. 分离控制信令与视频数据：可以使用不同的端口、不同队列、或者不同逻辑流，并配合不同的优先级策略
	5. I帧重传(PLI/FIR)：当I帧丢失时，可以使用PLI请求重传图像、用FIR刷新解码器或请求新的关键帧
