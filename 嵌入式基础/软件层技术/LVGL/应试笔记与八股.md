# 2 能否讲一下LVGL的渲染管线

LVGL的渲染主要由如下几个环节进行：
1. <font color="#c00000">脏标记</font>：当控件被改变时，LVGL并不会立即将控件重新绘制到屏幕中，而是将控件所在矩形标记为"无效"，即"脏矩形"
2. <font color="#c00000">脏矩形合并</font>：LVGL通过合并重叠或相邻的脏矩形，从而减少渲染次数
3. <font color="#c00000">VDB重绘</font>：当定时器触发重绘操作时，LVGL开始遍历无效区域，并计算无效区域中哪些控件需要重新绘制。无效区域内，被不透明遮挡的控件就无须重绘。
	- 其中，LVGL的绘制是使用一块较小的内存作为临时画布，并对图形进行绘制。该区域被称作<font color="#9bbb59">VDB</font>(<font color="#9bbb59">Virtual Display Buffer</font>)
4. <font color="#c00000">推送并刷新</font>：随后LVGL会调用用户提供的屏幕刷新回调，更新对应区域到屏幕中

# 3 什么是VDB，VDB和单双缓冲之间的关系

1. VDB是LVGL重绘脏矩形时的临时画布
2. 单双缓冲是CPU->屏幕之间的数据缓冲

# 4 DMA2D如何协助VDB绘图

1. DMA2D是STM32专门为图形处理设计的一个DMA控制器，其比普通的DMA多了一些基础的图形运算功能，例如：
	1. 颜色转换
	2. 颜色填充
	3. 图像混合
	4. 行偏移
2. LVGL可以利用DMA2D完成高速的颜色填充、图像混合和数据搬运等功能。

# 5 如何解决图像刷新时的撕裂问题

其他问法：
- 为什么双缓冲可以解决屏幕撕裂问题

1. 屏幕撕裂发生的原因是在屏幕显示显存数据的过程中，显存中的图像被CPU更新，导致上下半部显示画面有撕裂的情况。
2. 其解决思路为<span style="background:#fff88f"><font color="#c00000">阻止在LCD扫描期间同步数据</font></span>，解决方法有：
	1. <span style="background:#fff88f"><font color="#c00000">使用双缓冲机制</font></span>，一个缓冲负责向屏幕同步数据，一个负责接收来自于CPU的改动
	2. 使用有TE功能的LCD，TE会告诉CPU显示屏何时不会读取数据。不过该方法要求CPU有极高的写入速度，不实用。

# 6 LVGL是如何把收到的触摸信号转化为UI事件的？

其他问法：
- LVGL是如何接收触摸信号的
- 触摸信号是如何传递给LVGL的

1. LVGL是在定时器的 `lv_timer_handler` 中，定时轮询 `read_cb` 来接收驱动传递来的接收事件，而不是中断中直接通知LVGL

# 7 LVGL为什么要内置一个内存管理器

1. 无 `mmu` 系统的内存碎片问题，略
2. 无 `mmu` 系统的 `malloc` 时间复杂度不确定
3. 部分嵌入式环境可能未提供标准库实现
4. 可以通过自己实现的内存管理器监视内存使用情况

# 8 讲一讲LVGL的定时器回调和嘀嗒回调

1. LVGL的定时器回调(`lv_timer_handler`)
2. LVGL的嘀嗒回调(`lv_tick_inc`)主要用于向LVGL传递时间流逝信息，用于让LVGL基于时间信息完成动画或其他时基功能

# 9 讲一下LVGL是如何实现pybinding的

1. <font color="#c00000">预处理</font>：调用gcc对LVGL的SDK头文件(`lvgl.h`)进行预处理
2. <font color="#c00000">语法树解析</font>：调用 `pycparser` 对预处理后的头文件进行语法树解析
3. <font color="#c00000">binding代码生成</font>：自动根据模板生成胶水代码
